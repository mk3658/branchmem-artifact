# Protocol: Independent Adjudication of MAB-Derived Branch Conflicts

## Objective

Estimate whether the derived resolution labels used by the BranchMem
MemoryAgentBench extension agree with independent semantic judgments, and test
Contextual BranchGuard on calibration and deployment items separated by source
row.

## Population and sample

Primary plan: adjudicate all 270 released conflicts. If resources require a
subset, select at least 192 conflicts, stratified proportionally across all
eight source rows and then across predicate families, with a minimum of 12
items from every represented family. Fix the sample and analysis script before
labels are revealed.

## Annotators

Use three independent adult annotators proficient in English. None should be an
author of the benchmark construction. Record only a random annotator ID; do not
collect unnecessary demographic information.

## Blinding and presentation

For each conflict, show:

1. the relevant original MemoryAgentBench context or evidence span;
2. the common-ancestor value, if recoverable;
3. the two branch values in independently randomized left/right order;
4. the entity and predicate in readable form.

Do not show the parser-derived label, source/confidence metadata, model output,
or another annotator's decision. Randomize branch order separately for each
annotator and preserve the mapping in a private key generated by the supplied
script.

## Annotation questions

Annotators choose exactly one outcome:

- `LEFT`: the left branch should be retained;
- `RIGHT`: the right branch should be retained;
- `MERGE`: both contain compatible information and a combined value is needed;
- `UNRESOLVED`: the displayed evidence does not justify a unique resolution.

They also provide confidence from 1 to 5, quote or locate the decisive evidence
span, and give a short rationale. Items lacking an evidence span for a decisive
choice are flagged for quality review, not silently discarded.

## Adjudication

The primary semantic label is the majority of three independent responses. A
three-way tie or three distinct responses becomes `NO_MAJORITY` and is treated
as unresolved for automation evaluation. Report raw unanimity, pairwise
agreement, Fleiss' kappa, per-family agreement, and the distribution of
confidence. Do not resolve disagreements through an author-only judgment.

## Primary outcomes

1. Majority agreement with the hidden MAB-derived label, overall and by source
   row/predicate family.
2. Fraction judged uniquely resolvable versus merge/unresolved.
3. Context-conditional provenance reliability estimated from human-majority
   labels.
4. BranchGuard coverage, conditional wrong-commit risk, and worst-channel risk
   on held-out source rows.
5. The same metrics for BayesianSourceMerge, pooled calibration, always-follow,
   and always-abstain.

## Calibration/test separation

Use source-row-separated evaluation: four source rows for calibration and four
for testing, then rotate across all balanced row splits or perform leave-one-row
out analysis. Never place conflicts derived from the same source row in both
calibration and test for the primary result. Channel definitions must be fixed
before viewing labels. If the taxonomy is revised after viewing outcomes, use a
fresh holdout split and label that analysis exploratory.

## Statistical reporting

Use exact binomial intervals for per-channel reliability and a family-wise
correction across predeclared channels. Report raw counts, not only percentages.
For policy metrics, bootstrap source rows rather than individual conflicts. If
any channel has too few calibration items to certify, report abstention rather
than pooling it into a superficially safer average.

## Safety and privacy

The source dataset is public research material, but annotation sheets should
include only context needed for the decision. Remove accidental personal
identifiers if present. Annotators must be warned that medical or safety-related
examples are hypothetical research items and not advice.

## Model-panel substitution (what we actually ran)

The human study above is still open. To obtain *some* independent signal in the
meantime we ran the identical protocol with six model adjudicators, which is a
weaker instrument and is reported as one throughout the paper.

Panel:

| id | adjudicator | lineage |
|----|-------------|---------|
| ann1 | `gpt-5.4` | OpenAI |
| ann2 | `gpt-5.4-mini` | OpenAI |
| ann3 | `gpt-5.4-nano` | OpenAI |
| ann4 | `cross-encoder/nli-deberta-v3-small` | local, DeBERTa-v3 |
| ann5 | `llama3.1:8b` (Ollama) | local, open weights |
| ann6 | `roberta-large-mnli` | local, RoBERTa |

`ann1`-`ann3` share a vendor, so agreement among them overstates independence.
`ann4`-`ann6` share no vendor, no weights and no training data with them, and
form a vendor-independent sub-panel of the size this protocol asks for. Report
both tiers separately and never pool them into a single agreement number.

Everything the protocol controls is preserved: each adjudicator sees only the
numbered evidence, the ancestor value and the two candidates in an
independently randomised left/right order, with no source, no confidence, no
model output and no other adjudicator's answer; answers are de-blinded through
`PRIVATE_presentation_key.csv`.

A tier reaches a **verdict** when strictly more than half its members pick the
same candidate; abstentions never form a verdict. A malformed reply counts as
an abstention and is tallied separately, so an adjudicator's abstention rate is
never inflated by its own formatting failures.

Two evidence windows are run over all items (6 lines and 30 lines) so that
"the evidence does not determine this item" can be distinguished from "the
window was too narrow".

Anyone running the human study should ignore this section: it exists so that
the model-panel numbers in the paper can be reproduced and so that their
weakness relative to the human protocol is on the record.
